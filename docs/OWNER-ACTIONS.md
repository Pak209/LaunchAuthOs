# Owner actions — single decision checklist

Engineering is prepared on a private review branch. The smallest next approval is **one private staging setup**, with a named project/region and billing guardrails, external OAuth provider choice and one authorized test identity. It excludes live supplier submissions, live payments, user invitations and public plugin submission.

1. **Hosting and cost:** choose the staging Firebase/hosting project and region; approve billing if required. Review [inactive App Hosting example](customer-plugin/apphosting.staging.yaml.example): zero minimum and one maximum instance are proposed only, not deployed or a spending cap. Confirm console overrides, budgets/alerts, resource quotas and effective Cloud Run configuration after setup. A provider `hosted.app` hostname is sufficient; no custom-domain purchase is required. Approve secrets separately. Keep automatic rollouts and live commercial features off until acceptance.
2. **OAuth and identity:** select an established provider, approve a public PKCE client and exact callback/resource/audience/scopes. Specify verified stable subject-to-existing-Firebase-UID linking and revoke/disconnect policy. No email-only linking. Follow [provider decision](customer-plugin/PROVIDER-DECISION.md) and [private acceptance](customer-plugin/PRIVATE-ACCEPTANCE.md). The skeleton is not a working ChatGPT connection yet.
3. **Private acceptance:** approve deployment of this exact reviewed revision, Firestore rules/indexes and a synthetic/test account. Verify two-user isolation, expiry/revocation, reconnect/disconnect, report minimization, draft-save consent, support access and rollback. Only then record truthful operational verification flags.
4. **Data policy:** decide paid-order/approval/report retention and lawful account erasure/anonymization, source/history retention, backup retention and restoration of deletion fences. Name a support/privacy contact and response owner. Draft-project deletion is implemented; full account deletion remains explicitly blocked, not queued. No legal policy text was invented or published.
5. **Supplier and packages:** approve exact package revisions, included directories, customer prices and supplier cost/margin assumptions in [package contracts](PACKAGE_CONTRACTS.md). Confirm PRNow rights, costs, rate limits, refunds and ambiguous-submit reconciliation. Its `/api/v1/test` is key/balance validation, not a free submit sandbox. Separately authorize a minimum-cost supervised pilot if desired; no purchase or mandatory reseller deposit is assumed here.
6. **Payments and operations:** approve Stripe test configuration first, then signed webhook/partial-refund drills, job scheduling, monitoring, backups and support procedures. Live Stripe products/prices, provider submission and controlled-beta invitations each remain separate approval gates.
7. **SEO data:** for Google/Bing imports, supply an authorized property and exact export/API schema plus overlap/repeat rules. For AI referrals/conversions, select the analytics property, conversion events, consent, bot/test filtering, attribution window and retention. See [SEO dependencies](SEO-REMAINING.md). Missing access is unknown, not a zero measurement.
8. **Public release:** approve legal/support URLs and privacy content, complete the current OpenAI package and review requirements, and authorize public submission separately. Keep plugin tools free of digital-service sales, upsell and checkout; the plugin is useful launch management.

Reference: [Firebase App Hosting configuration](https://firebase.google.com/docs/app-hosting/configure) documents runtime limits and console precedence. No current deployed instance limit was inspected or changed by this work.
